# 정책 Ref 카드 템플릿

## 사용 원칙

루트 지침만으로는 하위 구현 AI가 반복 정책을 필수 입력으로 인식하지 못할 수 있다. 여러 하위 카드가 반드시 재사용해야 하는 규칙은 독립 지식 카드로 만들고 실제 적용 대상 카드 방향으로 `reuse-first` 지식선을 연결한다.

- 정책 카드는 `isWork=false`인 독립 지식 카드로 두며 구현 진행률에 포함하지 않는다.
- 공통 정책은 원본 카드 하나에서 관리하고 필요한 문서에 Ref로 연결한다. 독립 본문 사본을 반복 생성하거나 관련 없는 카드까지 일괄 연결하지 않는다.
- 루트에는 “해당 종류의 하위 카드를 생성하거나 위임하기 전에 정책 Ref 연결을 확인한다”는 게이트를 둔다.
- 대상 카드의 설명이나 체크리스트에는 정책을 적용했는지 관찰할 수 있는 완료 조건을 둔다.
- 위임 직전에 지식선의 방향과 정책을 재조회한다. 연결은 `정책 Ref → 적용 대상 카드` 방향이다.
- 프로젝트별 실제 기준, 경로, 해상도, 교체 조건과 금지 사항을 채운 뒤 사용한다.

## 더미 UI 시안 정합 원칙

**적용 대상**: UI 제작·변경·시각 검수 카드

```markdown
# 더미 UI 시안 정합 원칙

## 목적
최종 아트가 없어도 최신 기획서 시안의 정보 구조, 컴포넌트 구성, 상태와 사용자 흐름을 최대한 유사하게 재현한다.

## 필수 기준
- 최신 기획서의 렌더링 이미지와 텍스트·표를 함께 확인한다.
- 버튼, 탭, 잠김·선택·비활성·빈 상태, 팝업, 화살표와 복귀 흐름을 생략하지 않는다.
- 임의의 완성형 디자인을 새로 만들지 않고, 미확정 리소스만 명시적 플레이스홀더로 대체한다.
- 레이아웃 값은 직렬화된 Prefab·에디터 자산이 소유한다. 동적 계산이 불가피하면 별도 확인을 받는다.
- 지정 해상도와 대표 상태를 Unity Play에서 시안과 대조하고 캡처·차이를 기록한다.

## 대상 카드 완료 조건
- 사용한 시안 슬라이드와 상태가 명시돼 있다.
- Play에서 진입·조작·전환·복귀가 가능하다.
- 시안과 다른 부분은 누락이 아니라 사유·교체 조건이 기록된 차이다.
```

## 더미 데이터·Fixture/Provider 원칙

**적용 대상**: 데이터 모델, 상태, 저장, 서버 대체 구현 카드

```markdown
# 더미 데이터·Fixture/Provider 원칙

## 목적
서버 계약이 없어도 동일한 입력에서 동일한 상태를 재현하고, 추후 운영 연동을 경계 구현만 교체해 적용한다.

## 필수 기준
- UI와 도메인 로직이 Fixture 원문이나 운영 DTO를 직접 참조하지 않게 Provider 경계를 둔다.
- 정상·빈 값·오류·지연·재시도·재진입에 필요한 결정적 Fixture를 제공한다.
- 임시 ID·정렬·시간·저장 범위와 운영 교체 지점을 기록한다.
- 미확정 서버 동작을 확정 계약처럼 추측하지 않는다.

## 대상 카드 완료 조건
- 더미 Provider로 요구 상태를 반복 재현할 수 있다.
- 운영 연동 시 교체할 인터페이스와 남길 클라이언트 규칙이 분리돼 있다.
- 외부 대기 항목과 재개 조건이 추적된다.
```

## 기존 구현·프로토타입 재사용 원칙

**적용 대상**: 과거 버전 코드·Prefab·테스트·MnP 카드를 활용하는 분석·구현 카드

```markdown
# 기존 구현·프로토타입 재사용 원칙

## 목적
과거 산출물을 폐기하지 않되, 과거 완료 상태를 최신 기획의 완료 증거로 승계하지 않는다.

## 필수 기준
- 현재 통합 기준에서 자산 존재와 컴파일 여부를 확인한다.
- 최신 요구사항별로 `그대로 사용/수정 사용/교체/제거/구현 없음`을 판정한다.
- 과거 테스트·Play 결과는 비교 근거로만 사용하고 영향 범위를 다시 검증한다.
- 재사용 근거와 남은 차이를 요구사항 ID에 연결한다.

## 대상 카드 완료 조건
- 재사용한 파일·Prefab·계약·테스트가 구체적으로 기록돼 있다.
- 오래된 동작의 제거 또는 비활성화 필요 여부가 확인됐다.
- 최신 버전에서 요구되는 검증을 다시 통과했다.
```

## Unity Play 검증 원칙

**적용 대상**: 화면·입력·상태 전환·재진입·시각 검수 카드

```markdown
# Unity Play 검증 원칙

## 목적
컴파일과 단위 테스트만으로 확인할 수 없는 실제 사용자 흐름과 시안 정합을 검증한다.

## 필수 기준
- 최신 통합 기준과 지정된 Unity 인스턴스에서 실행한다.
- 요구사항 ID별 진입 조건, 조작, 기대 상태, 실제 결과를 기록한다.
- 대표 정상 상태뿐 아니라 빈 값·잠김·비활성·오류·재시도·닫기·재진입을 포함한다.
- 지정 해상도에서 겹침·잘림·오정렬과 Console 오류를 확인한다.
- 임시 오브젝트·씬 변경·검증 부산물을 정리한다.

## 대상 카드 완료 조건
- 요구사항별 실제 Play 결과와 재현 절차가 있다.
- 실패·미확인 항목이 완료에 포함되지 않는다.
- 캡처가 필요한 항목은 시안과 비교 가능한 증거가 있다.
```

## 요구사항 추적·완료 판정 원칙

**적용 대상**: 문서 정비, 통합 관리, 요구사항 감사, 최종 검수 카드

```markdown
# 요구사항 추적·완료 판정 원칙

## 목적
대표 기능 완료, 카드 진행률, 하위 AI 보고를 전체 기획 완료와 혼동하지 않는다.

## 필수 기준
- 모든 원본 단위를 계수하고 원자 요구사항 ID를 부여한다.
- 요구사항마다 주 소유 문서를 정확히 하나 지정한다.
- 부분 구현과 외부 차단을 완료 수에 포함하지 않는다.
- 구현 근거, 자동 검증, Play 증거, 잔여 작업과 재개 조건을 추적한다.
- 독립 검수는 diff가 아니라 최신 원본 요구사항 전체에서 시작한다.

## 대상 카드 완료 조건
- 미분류·미검증 요구사항이 0이다.
- 완료 항목마다 요구되는 증거가 있다.
- 종료 보고에 상태별 수치와 분모가 명시돼 있다.
```

## 외부 연동·교체 경계 원칙

**적용 대상**: 서버·최종 아트·애니메이션·사운드·정책 후속 카드

```markdown
# 외부 연동·교체 경계 원칙

## 목적
더미 클라이언트 완료와 운영 연동 완료를 분리하고 외부 대기 요구사항이 사라지지 않게 한다.

## 필수 기준
- 더미에서 확정할 클라이언트 동작과 외부 전달 후 교체할 항목을 구분한다.
- 필요한 API·DTO·권위 상태·에셋·정책, 현재 임시값과 교체 지점을 기록한다.
- 운영 계약을 추측해 고정하지 않는다.
- 대기 항목에는 소유자, 영향 요구사항, 전달물과 재개 조건을 둔다.

## 대상 카드 완료 조건
- 더미 경계가 실제 Play 가능한 상태다.
- 운영 교체가 UI·도메인 전체 재작성이 아닌 명시적 경계 변경으로 제한된다.
- 외부 전달 전에는 운영 완료로 집계되지 않는다.
```
