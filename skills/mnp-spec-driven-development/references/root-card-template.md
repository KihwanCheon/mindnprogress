# 최상위 카드 템플릿

아래 템플릿을 그대로 복제하기보다 현재 기능, 원본 형식과 버전 관계에 맞게 채운다. 중괄호 항목은 실제 값으로 교체하고 적용되지 않는 선택 절은 제거한다.

```markdown
## 기획서 기반 개발 실행 계약

### 목적
이 문서는 {문서명} 영역을 {최신 버전} 기획 기준으로 분석·분해·구현·검수한다. 대표 화면이나 수직 단면만 완성한 상태를 전체 완료로 판정하지 않는다.

### 원본 기준
- 최신 원본: {파일명·버전·전체 분량}
- 원본 업무/경로: {링크}
- 직전 버전: {버전·출처}
- 기존 구현 출발 버전: {버전·출처}
- 공용 산출물과 분석: {원본별 버전·해시·PNG/텍스트/표 목록·분석 출처·접근 경로}
- 담당 범위: {슬라이드·페이지·절}
- 담당 기능: {기능 목록}
- 제외 범위와 소유 문서: {항목 → 문서}

### 구현 위임 전 필수 분석
1. 최신 담당 영역 원본 분석
   - 텍스트·표와 렌더링된 시안 이미지, 상태, 화살표, 주석, 예외를 함께 확인한다.
   - 모든 원본 단위를 요구사항 또는 `요구사항 없음/참고 시안`으로 기록한다.
2. 기존 구현 출발 버전 → 최신 버전 전체 차이 분석
   - 추가/변경/유지/삭제/정책 미정으로 분류한다.
3. 직전 버전 → 최신 버전 변경 영향 분석
   - 원본 단위가 이동해도 번호가 아니라 내용과 의미로 대응한다.
4. 현재 구현·프로토타입 감사
   - 요구사항별로 그대로 사용/수정 사용/교체/제거/구현 없음으로 판정한다.

공통 분석은 출처·버전·범위가 확인되면 재사용한다. 문서 담당 AI는 담당 시안 이미지를 직접 확인하고 현재 구현과 대조하며, 공통 준비 완료를 담당 분석·개발 완료로 승계하지 않는다.

위 분석 결과와 요구사항 추적표가 완료되기 전에는 구현 카드를 위임하지 않는다.

### 권장 카드 구조
- 기획 기준
  - 최신 담당 영역 원본 분석
  - 기준 버전 → 최신 버전 차이 분석
  - 직전 버전 → 최신 버전 변경 영향 분석
  - 현재 통합 구현·프로토타입 감사
- 더미 클라이언트 구현
- 후속 연동
  - 서버·운영 정책
  - 최종 아트·애니메이션·사운드
- 통합·검수
  - 요구사항 전수 감사
  - 자동 검증
  - 실제 Play·시안 대조

기존 하위 카드와 검증 이력은 삭제하거나 완료 상태를 자동 승계하지 않는다. 최신 요구사항과 명확히 대응되면 보완하고, 오래된 기획과 구현이 섞였다면 `{최신 버전} 재정비` 분기를 만들어 기존 카드를 근거 Ref로 연결한다.

하위 실제 업무가 있는 루트와 중간 묶음은 집계 카드로 구성하고 직접 `done/100%`로 만들지 않는다. 진행률과 상태는 실제 하위 업무 결과에서 파생되게 한다.

### 요구사항 추적
모든 요구사항에 원본 위치, 버전 차이, 소유 문서, 구현 수준, 검증 상태, 차단 상태, 구현 근거, 자동 검증, Play 증거, 잔여 작업과 재개 조건을 연결한다. 하위 구현 카드는 담당 요구사항 ID 전체를 설명 또는 체크리스트에 포함한다.

### 필수 지식 연결
- 문서 담당 AI가 사용할 공통 정보: {원본 카드 → 이 문서의 Ref → 루트 지식선}
- 하위 구현·검수 AI에게 필요한 Ref는 실제 업무 카드에도 직접 연결한다. 루트 지식의 자동 상속을 가정하지 않는다.
- 실제로 재사용할 기존 구현·검증 카드: {Ref 목록과 정책}
- 더미 UI 제작·변경·시각 검수 카드는 같은 문서의 {시안 정합 원칙 Ref}를 source로, 대상 카드를 target으로 하는 `reuse-first` 지식선을 위임 전에 연결한다.
- 하위 AI는 원칙 카드의 `sharedKnowledge`를 먼저 읽는다.
- 대상 카드에는 기획 시안과 Play 결과를 직접 대조하는 완료 조건을 둔다.
- 지식선의 source, target, policy를 저장 후 다시 확인한다.

### 더미 구현 기준
- 서버와 최종 리소스가 없어도 결정적 Fixture/Provider와 더미 에셋으로 실제 진입·상태 변화·오류·재시도·복귀가 가능한 Play 흐름을 만든다.
- 더미라는 이유로 시안의 주요 구성, 문구와 선택·비선택·잠김·빈 상태·오류 상태를 생략하지 않는다.
- 외부 대기는 요구사항을 삭제하는 사유가 아니다. 더미 완료와 후속 교체 경계를 분리하고 전달물과 재개 조건을 기록한다.
- 정책 미정은 임시값, 적용 범위와 교체 지점을 명시한다.

### 검수와 완료 게이트
- 정책·상태·정렬·저장·대기열은 결정적 자동 테스트로 검증한다.
- UI 표시·버튼·팝업·전환·재진입은 실제 Play로 검증한다.
- 독립 검수자는 하위 AI의 완료 보고가 아니라 원본 요구사항 ID 전체를 확인한다.
- 부분 구현을 완료로 세지 않는다.
- 더미 구현과 외부 연동은 서로 다른 업무 카드와 완료 조건으로 관리한다.
- 더미 구현 카드의 명시된 범위가 구현·검증되면 해당 카드만 완료할 수 있으며, 이를 문서·제품 완료로 보고하지 않는다.
- 외부 전달물이나 결정이 필요한 업무 카드는 전달물과 재개 조건을 `waitingItems`에 기록하고, 대기가 해소되어 구현·검증이 끝나기 전에는 완료하지 않는다.
- 문서 전체는 소유한 필수 업무 카드가 모두 완료되고 외부 연동·정책 미정·미분류·미검증이 0개일 때만 완료로 판정한다. 루트 상태와 진행률은 서버 자동 집계를 사용한다.
- 종료 보고에는 전체/더미 구현 완료/최종 구현 완료/자동 검증/Play 검증/외부 차단/정책 미정/미분류·미검증 수를 명시한다.

### 버전 변경
기획이 갱신되면 원본 단위와 요구사항별 변경을 비교하고 영향받은 카드와 테스트를 재개한다. 이전 버전의 완료와 Play 증거를 자동 승계하지 않는다.
```

## 작성 시 확인

- 루트는 문서 AI가 전체 구조를 정비할 수 있을 만큼 범위와 게이트를 명확히 적는다.
- 세부 요구사항 전체를 루트에 복사하지 않고 추적 카드에 둔다.
- 프로젝트 특화 정책은 독립 지식 카드로 유지하고 필요한 하위 카드에 연결한다.
- 다른 문서가 담당하는 요구사항을 단순 제외하지 말고 소유 문서 링크를 남긴다.
- 외부 업무 생성·수정 권한은 루트 지시로 새로 부여되지 않는다.
