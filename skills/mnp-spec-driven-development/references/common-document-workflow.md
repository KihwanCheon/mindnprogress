# 공통 문서 운영

그룹 공통·통합 관리 문서를 최초 준비·계획과 최종 검증에 사용하는 절차다. Claude와 Codex, 총괄·문서 담당·하위 구현·검수 AI에 동일하게 적용한다.

## 역할별 적용

- **공통 담당**: 최초 준비에서 전체 원본·공용 산출물·소유권과 공통 지식을 준비한다. 최종 검증은 최신 원본 전체와 실제 통합 결과에서 시작한다.
- **문서 담당**: 공통 산출물과 루트에 연결된 Ref를 읽고 담당 상세 분석·구현 감사·하위 업무를 관리한다.
- **하위 구현·검수 담당**: 실제 업무 카드에 직접 연결된 Ref와 담당 원본을 읽는다. 공통 자료가 준비됐다는 이유로 직접 시안 확인이나 검증을 생략하지 않는다.
- 어느 역할이든 현재 요청과 승인 범위에 해당하는 일만 수행한다. 이 문서를 읽었다는 이유로 그룹 준비를 다시 하거나 새 업무를 시작하지 않는다.

## 운영 규칙

- **공통 문서는 최초 준비·계획과 개발 결과의 최종 검증을 중심으로 운영한다.** 개발 중 각 문서의 진행 상황을 반복 복사하는 상시 관리 문서로 사용하지 않는다.
- **최초 준비·계획:** 모든 기획 원본의 주소·개별 버전과 관계를 확인하고, 공용 PNG·텍스트·표, 전체 요구사항 분류, 문서별 담당 범위·주 소유권·기본 구조·완료 조건과 공통 정보를 준비한다. 공통 준비 완료를 개발 완료로 간주하지 않는다.
- **공용 산출물 재사용:** 원본 버전·해시, 산출물 목록과 접근 가능 여부가 확인된 PNG·분석 결과를 우선 재사용하며 불필요하게 재추출·재작성하지 않는다. 재사용하더라도 담당 시안 이미지의 직접 확인과 현재 구현 감사는 생략하지 않는다. 자료가 없거나 불일치하면 원인을 알리고 필요한 범위를 다시 준비한다.
- **공통 지식 전달:** 공통 정보는 원본 카드 하나에서 관리하고 하위 문서에 Ref 카드로 연결한다. 문서 담당 AI가 사용하는 Ref는 최상위 카드에 지식선으로 연결하고, 구현·검수 AI에게 필요한 지식은 실제 업무 카드에도 직접 연결한다. 루트 지식이 하위 카드에 자동 상속된다고 가정하지 않으며, 위임 전에 필요한 연결의 방향·정책과 원본 내용을 확인한다.
- **개발 중 책임:** 각 기능 문서가 세부 업무·구현·검증·결과를 관리한다. 공통 분석을 재사용하되 담당 요구사항의 상세 검토와 기존 구현 대조는 각 문서가 수행한다. 공통 결과를 받았다는 이유로 하위 문서의 검수 책임을 없애지 않는다.
- **최종 검증:** 공통 담당은 최신 원본 전체와 실제 통합 코드·Prefab·검증 증거를 대조하여 문서 간 누락·중복·연동 문제를 확인한다. 하위 완료 보고를 합산하는 것만으로 전체 완료를 선언하지 않으며, 더미 클라이언트 완료와 서버·최종 자산·정책 대기를 구분한다.
- **개발 중 예외 조정:** 기획·공통 계약·문서 간 담당 범위가 바뀌면 최종 검증까지 미루지 않고 영향받은 부분만 공통에서 조정하며, 변경된 실행 계획은 사용자 확인·승인을 받는다. 공용 코드·계약의 단일 변경 소유권은 계속 유지한다.
- **승인 범위 유지:** 공통 준비, 문서·Ref 정비, 구현 위임과 검증은 각각 사용자에게 승인된 범위에서만 수행한다. 전체 방향 승인을 문서별 실행의 일괄 승인으로 해석하지 않는다. 이 지침 자체는 시스템 기능 변경이나 추가 AI 위임을 승인하지 않는다.

## 승인 확인과 기준 변경

- 그룹은 사용자에게 전체 방향을 먼저 승인받고, 이후 문서별 실제 지시 전문을 보여 대상·계획 버전·허용 작업·제외 범위·완료 조건을 별도로 승인받는다. 일부 문서만 승인되면 나머지는 대기한다.
- 지시 전문에는 승인받은 계획과 사용자의 실제 승인 발언·확인 가능한 출처를 전달한다. 총괄은 `mindnprogress_send_group_document_instruction`으로 소속 문서의 루트 AI에 전달하며, 다른 문서의 구현 카드에 직접 위임하지 않는다. 문서 AI가 자기 문서의 하위 업무 위임을 담당한다.
- 총괄은 문서 AI의 실행을 스스로 승인하지 않으며, 수신 AI도 근거가 없거나 모호하면 제안만 반환하고 실행을 보류한다. 분석·제안 승인만으로 카드 정비나 구현을 위임하지 않는다. 지시의 대기·전달·응답 상태는 업무 완료가 아니다.
- 실행 전 최신 그룹 기준과 승인된 계획을 대조한다. 기획서 추가·제거·주소·개별 버전·목표·공통 지침·핵심 방향·담당 범위가 달라지면 영향받은 실행을 보류하고 재승인을 받는다. 자료나 승인 근거를 확인할 수 없을 때도 같은 원칙을 적용한다.
- 승인 대기 기록용 댓글·공유 지식·대기 항목도 별도 승인 없이 변경하지 않는다. 준비 완료·제안 종료·승인 대기를 개발 완료나 루트의 직접 `done/100%` 처리로 바꾸지 않는다.
