# AI 대화 시작 작업공간

모든 문서 기반 신규 대화는 같은 작업공간 규칙을 쓴다. 대화 목적은 전문을 바꾸지만 작업공간 우선순위는 바꾸지 않는다.

## 설정과 우선순위

- 상단 문서·그룹 이름의 편집 아이콘에서 이름과 선택 사항인 작업공간을 편집한다. 목록의 그룹 이름 편집도 같은 화면을 연다.
- 문서 설정 → 소속 그룹 설정 순으로 적용한다. 문서를 비우면 그룹을 상속하고 그룹도 비어 있으면 시작할 때 선택한다.
- 설정은 실행 머신별이며 `_ai-workspace-settings.json`에 별도로 저장한다. 문서 본문·진행률·대화·그룹 정렬 저장이 설정을 덮어쓰지 않는다. 각 대상·머신의 버전으로 동시 편집을 검사한다.
- 등록된 pool의 경로 및 그 아래 경로는 통합 작업공간으로 정규화한다. 저장된 pool ID를 현재 registry에서 해석하므로 worker를 신규 대화에 임의 배정하지 않는다.
- 문서 설정이 있으면 과거 대화의 다른 경로 때문에 다시 묻지 않는다. 지정한 경로가 없거나 접근할 수 없으면 그룹 또는 MnP로 대체하지 않는다.
- 문서를 그룹으로 옮기면 다음 신규 대화부터 현재 그룹 설정을 적용한다. 명시적 문서 설정과 이미 실행 중인 대화·위임은 그대로 유지한다.

## 시작 시 확인

- 기준이 없으면 연결된 문서 대화를 추천 후보로 사용한다. 문서 대화가 없으면 같은 그룹의 활성 문서를 참고한다. Ref·연결 해제된 대화와 다른 머신의 경로는 제외한다.
- 후보는 추천일 뿐이다. 하나만 있어도 자동 확정하지 않으며, 최근 사용 횟수·문서 제목·브라우저의 과거 자동 입력값으로 기준을 만들지 않는다.
- `AionUi에서 시작`을 누르면 미설정/불명확/사용 불가 경로는 확인 창을 연다. 직접 입력·가능한 환경의 폴더 탐색·최근 목록으로 선택한다.
- `작업공간 확인·설정…`과 시작 전 확인에서 여는 팝업의 `선택` 버튼은 경로 반영만 하고 AI 대화 시작 창으로 돌아간다. 이후 모델·MCP·스킬 등 나머지 옵션을 고른 뒤 `AionUi에서 시작`을 눌러야 대화를 시작한다. 선택 자체는 대화 탭·귀속 기록·시작 요청을 만들지 않는다.
- 적용 범위는 `이번 대화만 사용`(기본), `이 문서의 작업공간으로 설정`, `이 그룹의 작업공간으로 설정`이다. 그룹 저장은 별도 문서 설정이 없는 문서에만 적용한다. 문서가 없는 승인 진입은 일회성 선택만 제공한다.
- 문서·그룹 적용 범위는 `선택` 시 기준을 저장한다. 저장 후 화면 반영이 실패하면 저장 성공과 반영 실패를 구분해 알린다. 선택·취소는 요청·AI 옵션을 보존하고, 이후 실제 시작에서 경로와 기준을 다시 검증한다.
- API가 시작 직전에 경로·기준 토큰·그룹 소속을 재검사하고 WebUI 전송 경로도 귀속 기록과 비교한다. 설정 저장이나 추천 조회는 AI 대화를 시작하지 않는다.
- 메인 머신은 디렉터리 존재와 접근을 검사한다. 서브 머신 경로는 해당 머신별로 보관하며 메인 경로로 대체하지 않는다. 현재 서브 머신의 폴더 탐색 API가 없으므로 절대 경로 형식만 검사하며 UI에서 이 한계를 알린다.
- 최근 작업공간 목록 삭제는 명시적 문서·그룹 설정 삭제가 아니다. 기준을 해제하려면 이름 편집에서 작업공간을 비워 저장한다.

## API와 검증

- `GET /api/integrations/aionui/workspace-context?mapId=...&groupId=...&machineId=...`: 현재 설정·유효 경로·추천 근거·버전 토큰. 이름 편집의 그룹 조회는 mapId를 생략한다.
- `POST /api/integrations/aionui/workspace-settings`: scope(document/group), id, machineId, workspace, baseVersion. 그룹 저장을 문서에서 요청하면 mapId도 보내 소속을 재검사한다.
- 기존 options API는 모든 목적에서 mapId를 사용한다. 새 MCP 도구는 추가하지 않는다.
- 새 클라이언트는 attributions에 workspaceToken과 사용자 직접 선택 여부(workspaceConfirmed)를 보낸다. 빈 경로 또는 확인되지 않은 후보로 시작하던 이전 클라이언트는 새로고침해야 한다.
- 단위·격리 API: `node --test tests/ai-workspace-settings.test.mjs tests/ai-workspace-settings-api.test.mjs`
- 실제 Chrome 팝업: `MNP_BROWSER_TEST=1`로 `tests/ai-workspace-settings-browser.test.mjs` 실행. 다섯 진입 목적, 취소, 문서/그룹/일회성 저장, 이름 편집·설정 해제, 작은 화면·어두운 테마를 검증한다.

## 대화 시작 화면의 접힘 상태

- 작업공간·MCP 도구·스킬은 각각 접고 펼칠 수 있다. 저장값이 없으면 모두 펼치며 작업공간 기준 설명은 다른 보조 설명과 같은 8px 규격을 사용한다.
- 접으면 제목 오른쪽에 현재 작업공간 경로, 사용하도록 선택된 MCP 서버(필수 포함), 선택한 스킬 이름을 표시한다. 선택이 없으면 `선택 없음`으로 안내한다. 긴 값은 한 줄 말줄임으로 표시하고 마우스를 올리면 전체 값을 볼 수 있다. 펼치면 요약은 숨기며 기존 선택 개수와 계정별 접힘 상태 저장은 유지한다.
- 펼침 여부만 `_ai-dialog-preferences.json`에 로그인 계정별로 저장한다. 문서·실행 머신·진입 메뉴에 관계없이 다음 팝업과 다른 브라우저에서 복원하며 MCP·스킬 선택값이나 작업공간 기준은 변경하지 않는다.
- `GET /api/integrations/aionui/dialog-preferences`는 현재 계정의 `{ userId, sections: { workspace, mcp, skills } }`를 반환한다. `PATCH`는 `{ expectedUserId, sections }`의 불리언 부분 변경만 받아 다른 영역의 저장값을 보존한다. 로그인 계정이 바뀐 지연 요청은 거부한다.
- 저장 실패는 현재 화면의 상태를 유지하면서 재시도를 안내한다. 빠른 연속 조작과 팝업 재진입은 같은 계정의 요청 순서대로 처리한다.
- 적용에는 MnP 서버 재시작과 브라우저 새로고침이 필요하다. 단위·계정 분리·동시 저장·재시작 복원은 `tests/ai-dialog-preferences.test.mjs`와 `tests/ai-dialog-preferences-api.test.mjs`, 실제 접힘·키보드·재시도는 위 Chrome 팝업 테스트에서 검증한다.
