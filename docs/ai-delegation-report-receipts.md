# AI 위임 결과의 전달·수신 확인

하위 실행 완료와 상위 AI의 후속 응답 종료는 서로 다른 사건이다. 상위 AI가 결과를 받은 뒤 긴 턴에서 다음 작업을 조정하더라도 이전 하위 위임을 활성 상태로 남겨 후속 위임을 막지 않는다.

## 상태와 안전 조건

- `waiting-parent`: 미전달 결과. 상위 대화가 유휴 상태이면 기존 자동 보고로 전달한다. 상위 AI가 실행 중이면 별도 턴을 만들지 않는다.
- `waking-parent`: 결과 전달 요청 접수. `starting`이나 자원 대기만으로 수신 완료를 판단하지 않는다.
- `completed` + `reportStatus=received`: 하위 실행·필수 통합이 끝났고, 기존 요청의 대상 대화·실행 턴·전달 원문 해시로 전달을 확인했거나 담당 상위 AI가 정확한 결과 해시를 명시해 수신 확인했다.
- `parent-wake-failed`: 전달 확인 실패. 하위 실행 성공 여부와 분리해 표시하며, 조회나 재전달이 하위 작업을 다시 실행하지 않는다.

`completed`는 요구사항 검수나 프로젝트 전체 완료, 새 작업의 사용자 승인을 뜻하지 않는다. 상위 AI의 현재 실행 상태는 대화 런타임 표시에서 확인한다. 후속 위임에는 기존 승인 범위·카드 관계·대상 대화 런타임·작업공간 검사를 그대로 적용한다.

## 실행 중인 상위 AI의 결과 회수

1. `mindnprogress_list_ai_delegations`를 대상 카드 필터와 `includeResult=true`로 호출해 저장된 결과 원문, `resultHash`, `resultTurnId`, `updatedAt`을 확인한다. GET은 위임 상태를 변경하지 않는다.
2. 원문을 실제로 읽은 담당 상위 AI가 `mindnprogress_refresh_ai_delegation`에 `expectedUpdatedAt`과 `acknowledgeResultHash=resultHash`를 전달한다. 생략하면 기존 상태 조회 기능이다.
3. 서버는 불변 시작 대화·상위 카드, 현재 연결, 하위 실행·통합 완료, 결과 해시·턴을 검증한다. 다른 대화, 오래된 상태, 미캡처·변조 결과, 미완료 통합은 거절한다.
4. 수신 확인은 위임 메타데이터를 종결하고, 상위 대화에 사용자가 볼 완료 전문을 기록한다. 카드·문서 버전·코드·작업공간·승인을 바꾸거나 AI를 실행하지 않는다. 해당 대화의 후속 위임을 막던 활성 위임 기록은 해제되지만, 실제 실행 중인 대화를 중복 실행할 수는 없다.

## 사용자에게 보이는 완료 전문

- 수신 확인(`reportReceipt`)과 대화 기록(`reportArchive`)은 별도 근거다. AI가 MCP 응답을 읽었다는 사실만으로 사용자의 대화 화면에 전문이 남았다고 판단하지 않는다.
- 완료 결과를 보고할 때 전문과 고정 operation ID를 MnP에 먼저 저장한다. AionCore의 `POST /api/conversations/{id}/external-reports`는 원래 상위 대화에 일반 텍스트 메시지를 저장하고 실시간 이벤트를 보내지만 AI 실행·중단·작업공간 점유는 하지 않는다. 대화 소유자 인증과 기존 CSRF 경계를 사용한다.
- 상위 대화가 실행 중이어도 전문은 먼저 남는다. 유휴 시 자동 보고는 `historyMessageId`로 저장된 전문을 재사용하고 AI에 같은 지시를 전달한다. AionCore가 대상 대화·메시지·원문 일치를 검증하므로 화면에 전문을 다시 삽입하지 않는다.
- operation ID는 위임·상위 대화·하위 실행 턴·결과 해시로 고정한다. 응답 유실이나 MnP/Core 재시작 후에도 같은 메시지 ID를 사용하며 다른 본문으로 덮어쓰지 않는다. 재시도에는 처음 저장한 전문을 사용한다.
- 기본 목록은 `reportArchive`에서 긴 본문을 제외한다. `reportArchived`와 `reportArchivePending`으로 사용자 기록 여부를 별도로 확인할 수 있다. `completed`라도 수신 확인 직후 네트워크 장애가 있으면 전문 저장은 대기 중일 수 있다.
- 지원 여부는 `historyOnlyReports=true` capability로 확인한다. 구형 Core, 서버 장애, 응답 불일치이면 미완료 기록과 오류 코드를 보존하고 최대 60초 간격으로 재시도한다. 이 재시도는 AI를 실행하지 않는다. 새 완료 보고의 자동 실행은 전문이 저장될 때까지 기다린다.

MCP 도구 수는 늘리지 않는다. 기본 목록에는 긴 원문을 포함하지 않으며, 전체 대화의 최신 응답으로 과거 위임 결과를 대체하지 않는다.

## 재시작 및 기존 기록

재시작 전 `running` 또는 실행 후 중지 상태로 관측한 동일 보고 요청의 대화·턴·전문 해시와 결과가 남아 있으면, 그 근거로 보고 수신을 복원한다. 이미 전달된 결과는 상위 대화가 중지되거나 요청 기록이 만료되어도 다시 보내지 않는다. `reportReceipt`에 수신 방식·시각·대화·턴·해시를 보존한다.

과거 `parent-acknowledged`로 완료됐지만 전문이 없는 기록은 보존된 결과와 수신 확인의 대화·턴·해시가 일치할 때 자동으로 전문을 보충한다. `dispatch-delivered` 기록은 기존 자동 보고 메시지가 있으므로 보충 대상이 아니다. 삭제·폐기·복구 중이거나 무결성이 맞지 않는 결과는 자동 보충하지 않는다.

배포 순서는 AionCore 소스 반영 → 사용자의 Core 빌드·AionUi 재시작이다. MnP를 먼저 재시작해도 대기 기록은 보존되며, 새 Core의 capability가 관측되면 별도 수동 재전달 없이 기록을 보충한다. 실제 A/B 대화의 보충 확인은 새 Core 적용 후 가능하다.

미전달 결과는 상위 대화가 유휴 상태일 때 자동으로 전달하므로 재시작 후 상위 AI가 다시 실행될 수 있다. 전달 근거가 없거나 실패한 기록까지 일괄 완료 처리하지 않는다. 그런 기록은 결과를 읽은 담당 상위 AI의 명시적 수신 확인 또는 기존 결과 전달 재시도 절차를 사용한다.
